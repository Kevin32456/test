# 甩狗（Shuai Gou）上架前內容 Roadmap

## 目標玩家體驗

玩家在 30 秒內知道「我要活到最後」、在第一局內學會走位／傳球／Blink，並在一局結束後知道自己下一局要改變什麼。核心情緒是「球越燙越急，但我還能靠判斷翻盤」。

## 目前內容審查

### 核心循環

```text
選角色與房間 → 倒數 → 走位／引狗 → 傳球／Blink → 出局或獲勝 → 再開一局
```

- `PASS`：伺服器權威、傳球飛行、狗壓力累積、死亡停頓與最後存活者勝負已成立。
- `WARN`：新手第一局仍需要非開發者觀察證據；程式內已有可重看的指南、練習房與結算下一步，但尚未證明第一次遊玩不需要外部說明。
- `UNVERIFIED`：8 台不同裝置／網路的真人對局、長時間重玩意願、音效與正式美術方向。

### KEEP / CHANGE / CUT / TEST

| 決策 | 內容 | 原因 |
|---|---|---|
| KEEP | 熱土豆 + 甩尾狗核心 | 同時產生走位、傳球時機與派對陷害決策 |
| KEEP | 右鍵移動／傳球 + Space Blink | 操作少但有足夠位置與時機表現 |
| CHANGE | 第一局教學、回合結果、角色選擇資訊 | 直接降低新手流失，不改變伺服器規則 |
| TEST | 第二張競技場、特殊回合規則 | 先用 playtest 證明核心可重玩，再擴大內容量 |
| CUT | 目前加入職業技能、養成、商店與排位 | 會改變平衡與 Steam 上架範圍，等核心回合穩定後再決定 |

## Milestones

### A. 第一局可理解（本次完成）

- 大廳顯示可收合、可重看的玩法指南。
- 倒數畫面再次提示目標與三個主要操作。
- 角色卡加入風格與描述，但明確標示不改變戰鬥數值。
- 結束狀態顯示勝者、本人存活／出局、出局原因、下一步提示與下一局入口。

### B. 第一個可重玩的內容包（最小 proof 已完成）

- [x] 實作可重玩的「練習／教學房」：單一玩家即可練習走位、傳球與 Blink。
- [x] 三步驟有完成條件、完成提示、重新練習與回到大廳入口。
- [x] 沿用 shared 的移動、Blink、傳球速度與競技場邊界常數；不複製多人伺服器房間狀態。
- [x] 練習房不保存不可逆進度，不建立 Socket.IO room／player；關閉頁面後連線可清理。
- [ ] 以非開發者玩家觀察第一局完成率與卡點，再決定是否增加提示或調整節奏；目前僅完成開發者／瀏覽器 smoke。
- 測試記錄模板：`docs/PLAYTEST-OBSERVATION.md`。

### C. 回合變化（第二競技場最小 slice 已完成）

- [x] 先做一個視覺／路線不同、規則相同的第二競技場：月影庭。
- [x] 用同一個競技場資料介面支援邊界與裝飾，不先引入障礙物碰撞。
- [x] 以 teach → test → twist → mastery 節奏安排地圖，而非只換顏色；階段由伺服器快照推進，月影庭改變路標與路線提示，不改物理。
- [ ] 8 人與高延遲下驗證出生點、傳球可讀性與狗的甩尾路徑；自動化 gate 已驗證 8 個 distinct spawn、pass flight 與狗路徑／轉向，真人跨裝置仍待測。

#### 第二競技場目前內容

- 月影庭：冷色月庭、四個月燈路標、內圈與菱形動線。
- 競技場由房間快照同步；大廳可切換，倒數／對局期間鎖定。
- 月影庭與朱印圓場共用圓形邊界、出生點與核心規則；月燈是視覺路標，沒有障礙物碰撞。
- 本機／公開雙玩家 smoke 已確認兩頁收到同一張場地；公開 8 人 gate 已確認 spawn、pass flight、狗路徑與延遲行為，下一步仍是不同裝置玩家的可讀性觀察。
- 階段提示已加入短暫文字與音效；仍需非開發者觀察是否真的理解「下一步」。

## 本路線的非目標

- 不在沒有 playtest 證據前替角色增加不同速度、Blink 或傳球能力。
- 不把 Steamworks、伺服器擴容、付款或商店提交混進內容開發。
- 不先建立複雜的存檔、經濟或排位系統；目前是短局派對遊戲，先證明每局值得重開。
