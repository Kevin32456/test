# 甩狗（Shuai Gou）— Game Design Brief v1

> 100% 還原 WC3 自製地圖核心玩法。KaMe、模式變體、新內容留 v2。

---

## 1. 概述

| 欄位 | 內容 |
|------|------|
| 類型 | 多人派對 / 鬼抓人 + 熱土豆 |
| 人數 | **4 人連線**（原型可 2–4 人開局測試） |
| 單局時長 | 短局（目標 3–8 分鐘） |
| 平台 | **網頁**（Vite + Phaser 3 + Socket.io） |
| 鏡頭 | 俯視 2D（推測，依 WC3 地圖） |

### 玩家幻想

> 我必須在甩尾狗漂移撲過來之前，把球傳給隊友；越久不傳，狗越快，越來越來不及。

### 設計支柱

| # | 支柱 | 驗證方式 |
|---|------|----------|
| P1 | 燙手球 | 持球者心率上升、頻繁傳球 |
| P2 | 持球不能 Blink | 規則強制，無球者才有逃生技 |
| P3 | 持球時間 → 狗加速 | 拖時間明顯更危險 |
| P4 | 甩尾可讀 | 玩家能靠走位/卡邊緣讓狗繞圈 |
| P5 | 派對陷害 | 玩家故意傳向貼臉隊友 |

### 反支柱

- 不做蓄力 KaMe（v1）
- 不做飛毛腿 / 風火輪（v1）
- 不做障礙物、養成、道具

## 2. 核心循環

```text
隨機開球
    ↓
┌─────────────────────────────────────┐
│ 持球者被狗鎖定                       │
│  狗速 = f(持球時間) ↑               │
│  持球者：移動 + 右鍵傳球（無 Blink）  │
│  無球者：移動 + Blink（CD）          │
└─────────────────────────────────────┘
    ↓ 傳球成功
新持球者（計時重置）→ 狗改追新目標
    ↓
狗碰到持球者 → 死亡 → 觀戰
    ↓
最後存活者 → 勝利
```

---

## 3. 玩家狀態機

```text
                    ┌──────────┐
         開局/傳球   │  ALIVE   │
        ──────────► │  (無球)  │◄──────────┐
                    └────┬─────┘           │
                         │ 接到傳球         │ 傳出球
                         ▼                 │
                    ┌──────────┐           │
                    │  ALIVE   │───────────┘
                    │  (持球)  │
                    └────┬─────┘
                         │ 被狗碰到
                         ▼
                    ┌──────────┐
                    │   DEAD   │ → 觀戰
                    └──────────┘
```

### 3.1 ALIVE（無球）

| 能力 | 說明 |
|------|------|
| 移動 | 右鍵點地，角色走向目標點 |
| Blink | 可用，有冷卻時間 |
| 接球 | **不可主動接**；僅在被隊友右鍵選中時成為持球者 |
| 傳球 | 不可用 |

### 3.2 ALIVE（持球）

| 能力 | 說明 |
|------|------|
| 移動 | 右鍵點地（速度待定，見 §8 開放問題） |
| 傳球 | 右鍵點**存活**玩家；不可點死人 |
| Blink | **禁用** |
| 接球 | N/A（已在持球） |

### 3.3 DEAD

- 無操作權限
- 攝影機跟隨存活玩家或自由觀戰（待定）
- 不可被傳球

## 4. 輸入與優先級

| 操作 | 輸入 | 條件 |
|------|------|------|
| 移動 | 右鍵點地 | 存活 |
| 傳球 | 右鍵點存活玩家 | 存活且持球 |
| Blink | 快捷鍵（建議 Space / B） | 存活且無球且 CD 結束 |

**點擊優先級（持球時）：**

1. 若右鍵命中存活玩家 collider → **傳球**
2. 否則若右鍵命中地面 → **移動**

**點擊優先級（無球時）：**

- 右鍵點地 → 移動
- 右鍵點玩家 → 無效果（不可主動要球）

---

## 5. 傳球規則

| 規則 | 說明 |
|------|------|
| 目標 | 必須是存活玩家 |
| 禁止 | 死人、自己、（待定：是否在 Blink 中的無球者） |
| 軌跡 | v1 建議**瞬間轉移**持球權（與 WC3 give 指令一致）；飛行軌跡可 v2 |
| 接球後 | 立即成為持球者；狗改追新目標；**持球計時器歸零** |
| 硬直 | 待定：接球後 0.1–0.3s 內是否禁止 Blink（即使已無球） |

## 6. 狗（AI）

### 6.1 行為

- 永遠鎖定**當前持球者**位置
- 持球者死亡 → 若球在死者身上則**隨機分配給存活者**（或球落地，需確認原版；**暫定：隨機 alive 開球邏輯一致**）
- 僅在「持球者存活且持有球」時造成擊殺

### 6.2 速度模型

```text
speed(t) = baseSpeed + holdTime × accelPerSecond

t = 當前持球者連續持球秒數
傳球成功 → t 重置為 0
```

| 參數 | 原型建議 | 備註 |
|------|----------|------|
| baseSpeed | 略慢於玩家步行 | 給初期喘息 |
| accelPerSecond | 需 playtest | 5–10 秒應進入高壓 |
| maxSpeed | 建議有上限 | 避免不可閃的必殺 |

### 6.3 甩尾物理（Type A — 飄移）

**設計意圖：** 狗直線追擊快，急轉彎時因慣性外甩，路徑可預判。

**實作要點：**

```text
desiredVelocity = normalize(target - pos) × speed(t)
actualVelocity  = lerp(actualVelocity, desiredVelocity, turnRate) 
                  // 或使用角速度上限 + 側向摩擦力

constraints:
  - maxTurnRate（度/秒）隨 speed 略增或略減
  - 高速時轉彎半徑變大 → 「甩尾」感
  - 視覺：狗 sprite 朝向 actualVelocity 方向
```

**玩家技巧：**

- 貼 arena 邊緣跑，逼狗大角度轉彎
- 在狗外甩時傳球，新目標在狗反方向 → 狗需大角度折返

### 6.4 擊殺判定

- 狗 collision body 與**持球者** overlap → 持球者死亡
- 狗穿過無球者：**不擊殺**（待定，需確認原版）

## 7. 對局流程

```text
1. 大廳 / 匹配（人數到齊）
2. Countdown 3…2…1
3. 隨機選一存活玩家賦予球
4. 自由遊玩
5. 僅剩 1 人 → 勝利畫面 → 重開
```

| 階段 | 說明 |
|------|------|
| 開球 | uniform random among alive players |
| 中途加入 | v1 不做 |
| 平手 | 不適用（至剩 1 人） |

|------|-----|
| 形狀 | 圓形或矩形開闊 arena |
| 障礙 | 無 |
| 邊界 | 硬牆，玩家與狗不可穿出 |
| 尺寸 | 需 playtest；原型建議 20–30 玩家身位寬 |

## 9. UI / 回饋

| 元素 | 說明 |
|------|------|
| 持球標記 | 球在頭上 / 腳下光環 / 持物 sprite |
| 狗目標 | 可選：狗頭上箭頭指向持球者 |
| Blink CD | 無球者技能圖示 CD 轉圈 |
| 存活人數 | 「剩 N 人」 |
| 死亡 | 擊殺音效 + 灰屏/幽靈化 → 觀戰 |
| 勝利 | 全屏勝利 + 重開 |

## 10. 開放問題（Prototype 前需定）

| # | 問題 | 建議預設 |
|---|------|----------|
| Q1 | 平台 | Godot 4 2D 或 Phaser 網頁 |
| Q2 | 人數 | 原型 4；正式 8–12 |
| Q3 | 持球者移動速度 | 與無球相同（先簡化） |
| Q4 | 死者球權 | 死者被追殺時死亡 → 球**隨機給存活者** |
| Q5 | 狗碰無球者 | 無傷害 |
| Q6 | Blink | CD 3s，距離 5 身位，無無敵幀（待測） |
| Q7 | 加速曲線 | 線性 + maxSpeed cap |
| Q8 | 連線 | 原型單機 1 人 + AI；再 LAN |

## 11. 最小可玩原型 — 驗收標準

### Definition of Ready

- [x] 規則文件完成
- [ ] 平台與引擎選定
- [ ] 輸入映射確定

### Definition of Done（Prototype Gate）

| # | 驗收項 | 通過條件 |
|---|--------|----------|
| T1 | 移動 | 右鍵點地，角色抵達 |

| T8 | 擊殺 | 狗碰持球者 → 出局 |
| T9 | 勝負 | 剩 1 人顯示勝利 |
| T10 | 觀戰 | 死人可觀看存活者 |
