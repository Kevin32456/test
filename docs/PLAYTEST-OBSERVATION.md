# 甩狗 Playtest Observation

## 目的

用不熟悉規則的玩家觀察兩件事：

1. 玩家是否能不看外部說明完成單人練習房三步驟。
2. 玩家是否能在第一局多人遊戲中理解「持球者是狗的目標」、傳球時機與 Blink。

這份表記錄行為，不在測試途中教玩家。若玩家卡住，先記錄卡點，再於測試結束後詢問原因。

## 主持人快速執行版

1. 使用公開 staging：<https://test-vccb.onrender.com>；測試前記錄 `GET /ready` 的完整 JSON 與 commit，並使用乾淨的瀏覽器／無痕視窗，避免舊的語言、房間或音效設定影響結果。
2. 單人練習只說：「請試著把這個練習完成。」不要說右鍵、Space 或球的規則；把玩家第一次尋找操作的時間與原話記下來。
3. 第一局多人只說：「請和另一位玩家玩一局。」不要在倒數前解釋持球者、狗、傳球或 Blink；若玩家主動詢問，先記錄問題，再於測試結束後回答。
4. 月影庭 8 人測試至少使用兩種不同網路（例如家用 Wi‑Fi＋手機熱點），記錄裝置、瀏覽器、網路類型、房間碼、開始／結束時間、斷線／重連與玩家對出生點、傳球路線、狗甩尾、四個階段提示的原話。
5. 測試結束後才填寫本表的結論；不要把主持人的提示、開發者自行操作或自動化 gate 填成玩家自行理解的證據。

建議測試者先完成練習房，再與另一位玩家完成至少 3 局；若要驗收長 replay，使用 `npm run test:staging:long` 的 3×15 秒結果作服務證據，另記錄真人是否願意主動再玩。

### 練習房通過條件

- 不依賴外部說明完成 3／3。
- 每一步第一次卡住不超過 15 秒，或玩家能自行重新閱讀提示後繼續。
- 完成後能說出正式對局的主要目標與三個操作。
